T
Reporter Engine — Three Access Tiers
Same engine, progressively more control
Tier 1 - Novice

Zero-config EDA

System runs a full opinionated analysis automatically. User just provides the file.

from datainsight_lite import analyze # One-liner, full report analyze("customers.csv") # generates report.html with: # dataset profile # all univariate plots # correlation heatmap # outlier summary # missing value chart # text insights
Tier 2 - Intermediate

Selective Analysis

Choose which modules, columns, and chart types to use.

from datainsight_lite import Reporter r = Reporter("customers.csv", mode="intermediate") r.select( modules=["univariate", "correlation"], columns=["Age", "Income"], chart_type="plotly" ) r.render("report.html") data = r.to_json()
Tier 3 - Pro

Dashboard Config

Define every chart, layout, theme, and analysis parameter.

from datainsight_lite import ( Reporter, ReportConfig) cfg = ReportConfig(theme="dark") cfg.add_chart("histogram", col="Age", bins=40) cfg.add_chart("scatter", x="Age", y="Income", color="Gender") cfg.add_section("outliers", method="zscore") cfg.set_layout(columns=3) Reporter("customers.csv", config=cfg).render("d.html")

ReportResult — unified output object
@dataclass class ReportResult: profile: DatasetProfile # shape, dtypes, missing, cardinality univariate: List[ChartResult] # one entry per analyzed column bivariate: List[ChartResult] # one entry per pair correlation: ChartResult # heatmap outliers: OutlierResult # col to count, method, affected rows insights: List[str] # auto-generated text observations metadata: ReportMetadata # mode, timestamp, config snapshot def to_html(self, path: str) -> None: ... def to_json(self) -> dict: ... def to_pdf(self, path: str) -> None: ... # requires [pdf] extra
ChartResult — unified chart container
@dataclass class ChartResult: chart_type: str # "histogram" | "scatter" | "heatmap" | ... columns: List[str] plotly_json: dict | None # serializable — react-plotly.js renders directly mpl_base64: str | None # base64 PNG for HTML reports title: str insights: List[str] # per-chart observations

@dataclass class ReportConfig: theme: str = "light" # "light" | "dark" | custom hex dict layout_cols: int = 2 charts: List[ChartSpec] = field(default_factory=list) sections: List[SectionSpec] = field(default_factory=list) def add_chart(self, chart_type, **kwargs) -> "ReportConfig": ... def add_section(self, section, **kwargs) -> "ReportConfig": ... def set_layout(self, columns: int) -> "ReportConfig": ... @classmethod def from_yaml(cls, path: str) -> "ReportConfig": ... @classmethod def from_dict(cls, d: dict) -> "ReportConfig": ...

Open Design Decisions
Resolve before Phase 1 implementation begins
1. Session storage for the WebApp?
In-memory dict (simple, lost on restart) vs. Redis (persistent, multi-user) vs. temp files. Start with in-memory + tempfile backup; add Redis as optional extra later.
2. React chart library?
react-plotly.js (matches Python backend, zero translation) vs. Recharts/Visx (lighter bundle). react-plotly.js recommended — Python already emits Plotly JSON, no transformation needed in frontend.
3. Auto-insights text (Novice mode)?
Rule-based generation (deterministic, no deps) vs. LLM-powered narration (richer). Phase 1: rule-based. Later: optional LLM layer behind [insights] extra.
4. React build distribution?
Commit build output into the Python package (no Node required at install time) vs. build on-demand. Commit build output — most practical for pip install users.
5. Training dashboard framework (Phase 7)?
Flask + Plotly.js (lightweight, consistent with existing plotly dep) vs. Dash vs. TUI. Flask + Plotly.js recommended.
6. Package name and structure?
Keep datainsight-lite short-term. Rename to datainsight when scope justifies. Also flatten double-nesting: datainsight_lite/datainsight/ to datainsight_lite/.
